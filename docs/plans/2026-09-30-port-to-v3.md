# Port Scripta Live from compiler v2 to v3

**Goal:** Replace `vendored-compiler/` (a copy of `scripta-compiler-v2`) with a copy of `scripta-compiler-v3`, and adapt the app so the web version (`src/MainSQLite.elm`) builds and works as before.

**Source:** `../scripta-compiler-v3/src`, pinned at commit `f22b9ae` (2026-09-30). v3 is mid parser-refactor on `main`, so the port records the exact commit it copied.

**Toolchain:** v3 declares Elm 0.19.2, but it compiles under 0.19.1 (verified with the v3 Demo). The app stays on 0.19.1. Build with `~/.elm/elm-tooling/elm/0.19.1/elm`, because `/usr/local/bin/elm` is 0.19.2.

## What changes between v2 and v3

| Area | v2 (current) | v3 |
|---|---|---|
| Entry API | `ScriptaV2.DifferentialCompiler` (`init`, `update`, `editRecordToCompilerOutput`) with `EditRecord` | `Scripta` (`parse`, `reparse`, `render`) with an opaque `Document` |
| Output | elm-ui `Element MarkupMsg` | `Html Scripta.Event` (`title`, `body`, `toc`, `banner`) |
| Messages | `ScriptaV2.Msg.MarkupMsg` (`SendLineNumber`, `ToggleTOCNodeID`, `SelectId`, …) | `Scripta.Event` (`ClickedId`, `HighlightedId`, `ClickedFootnote`, `ClickedCitation`, `ClickedImage`, `ClickedLink`) |
| Options | `CompilerParameters`: lang, theme, filter, widths, `selectedId`, `idsOfOpenNodes`, `editCount`, … | `Scripta.Options`: theme, filter, window width, content width, TOC, sizing, max level |
| Languages | Scripta, MiniLaTeX, SMarkdown, Markdown | Scripta only (the app only ever uses Scripta, so nothing is lost) |
| Editor→preview highlight | Compiler highlights `selectedId` | `Scripta.Document.idsContainingSource`, with the highlight applied by CSS/JS (as the v3 Demo does) |
| Preview click→editor | `SendLineNumber` sets the CodeMirror `editordata` attribute | `ClickedId id`; the app then reads `data-begin`/`data-end`/`data-lines` from the element (the v3 Demo pattern) |
| TOC | `ScriptaV2.Compiler.viewTOC`, with expandable nodes | `output.toc`, no expand/collapse |
| LaTeX export | `Render.Export.LaTeX.export`/`rawExport` | Same functions exist in v3 (internal, but reachable because the source is vendored) |
| LaTeX→Scripta import | `Render.Export.LaTeXToScripta.translate` (a v2 module) | Not in v3. Use `vendored-converter/src/LaTeXToScripta.convert`, which is standalone. |
| Theme colours | `Render.Theme`, `Render.NewColor` | Not in v3. Move the palette into the app. |

## Steps

1. **Branch and baseline.** Create a branch `port-to-v3` from `main` and commit the current working tree there as the v2 baseline, so the port diff is clean.
2. **Swap the vendored source.** Replace `vendored-compiler/src` with v3's `src` (dropping `TestData.elm`) and add `vendored-compiler/VERSION.md` recording the commit. Add `vendored-converter/src` to `elm.json` source-directories. Align dependencies with v3 (for example `maca/elm-rose-tree`).
3. **App-owned types.** Replace `ScriptaV2.Settings.DisplaySettings` and `CompilerParameters` in `Common/Model.elm` with an app record that holds `Scripta.Options` inputs plus app state (selected id). Replace `EditRecord` with `Scripta.Document`, and `CompilerOutput` with `Scripta.Output Scripta.Event`.
4. **Theme and colours.** Copy `Render.NewColor` into `src/` (for example `Color/Palette.elm`), and update `Theme.elm` and `Style.elm` to use it and `Scripta.Theme`.
5. **Compile path in `MainSQLite.elm`.** `init` becomes `Scripta.parse` and `update` becomes `Scripta.reparse` (plain `parse` on document switch), with render calls for the view. Remove the `lang` plumbing.
6. **View.** In `Common/View.elm`, wrap the `Html` body and TOC with `Element.html`, and map `Scripta.Event` to a new `Common.CompilerEvent` message.
7. **Editor and sync: adopt the v3 Demo's editor.**
   - Replace `assets/codemirror-element.js` with the Demo's `codemirror-element.js` (566 lines, Scripta syntax highlighting, sync-highlight field). It registers the same `codemirror-editor` tag and emits `text-change` with the same `{position, source}` detail the app already decodes.
   - The Demo loads CodeMirror from esm.sh through an import map. Instead, bundle it locally with the existing rollup setup in `editor-prepare/` (every package it imports is already installed there), so the web app and Tauri builds need no CDN.
   - Adopt the Demo's sync model, whose JS lives in its `index.html`, and move that JS into the app's `index-*.html`:
     - Preview → editor: `ClickedId` → `selectInEditor` port (line, begin, end, numberOfLines); a mouse selection in the preview maps to an editor range.
     - Editor → preview: Ctrl+S emits `sync-to-rendered`, which highlights and scrolls the matching element.
     - Footnote and citation clicks: `scrollToElement` port. ESC clears highlights and restores the scroll position.
   - This replaces the old editor's `editordata`/`selection`/`refineselection` attributes and its `selected-text`/`cursor-change` events, along with `matchingIdsInAST`. Any other app feature that uses those gets ported or dropped, and I'll list which.
8. **Exports.** Point LaTeX export and raw export at v3's `Render.Export.LaTeX` using v3's `RenderSettings`. For PDF, re-implement `getImageUrls` over the v3 forest. Switch LaTeX import to `LaTeXToScripta.convert`.
9. **Other entry points and dead code.** Port `MainLocal.elm` and `MainTauri.elm` the same way (they share `Common`). Leave `Main.elm` and `ViewScripta.elm` unported and note that they are broken. Delete the dead and test-only files: `Debug*.elm`, `Test*.elm`, `QuickTest.elm`, `MinimalHrefTest.elm`, `Export.elm`, `Download.elm`, `Util.elm`, `EditorSync.elm`.
10. **Verify.** Build `MainSQLite`, then check in the browser at http://localhost:8012: rendering, math, editing, preview↔editor sync, TOC, theme toggle, new/load document, LaTeX export, Markdown and LaTeX import.

## Known behaviour changes

- The TOC no longer expands or collapses.
- New editor: the v3 Demo's CodeMirror setup (its key bindings, theme and Scripta highlighting). Editor → preview sync becomes Ctrl+S on a selection instead of automatic on selection.
- LaTeX import uses a different converter, so its output will differ from v2's `translate`.
- Anything v3 renders differently from v2 (block names, styling) will show up in existing documents.

## Outcome (2026-09-30)

Done on branch `port-to-v3`. MainSQLite, MainLocal and MainTauri compile against v3 `f22b9ae`. MainSQLite and MainLocal were smoke-tested in headless Chrome: render, math, edit/reparse, math re-render on edit, TOC, theme toggle, Ctrl+S sync, and rendered-selection → editor sync. MainTauri was compile-checked only (it needs the Tauri runtime). LaTeX export, image-url extraction and LaTeX import were checked in an Elm worker.

Differences from the plan:
- The rendered output is kept in the model (`compilerOutput`) and re-rendered only when the source or options change, rather than rendering in `view`.
- Plain clicks on rendered text do nothing in v3 (only TOC entries and internal links emit `ClickedId`). Rendered → editor sync is by selecting text, as in the v3 Demo.
- v3 element ids use 0-based line numbers; `editor-sync.js` converts them to CodeMirror's 1-based lines.
- v3 filters `title`/`document` blocks at parse time, so `ScriptaExport` re-parses without the filter for LaTeX/PDF export.
- `Widget.elm` was split: the `Model`-based widgets used only by `Main.elm` moved to `MainWidget.elm`.

Not done: `Main.elm` and `ViewScripta.elm` (as agreed); `run.sh` / elm-watch still use the `elm` on PATH (0.19.2), which fails on this project.
